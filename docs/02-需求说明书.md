## 1. 课题背景与目标

《2021 消耗量标准及计算规则（安装工程）》以印刷表格形式编排：横向按子目展开，纵向列人材机，一个子目在书上是**一列**。实训要求把这套标准数字化，因此需要：

1. 把标准中的分部分项人材机消耗量转成结构化数据（已完成：两个长表文件，2395 条记录）；
2. 提供一个查询界面，让使用者能按「分部 → 分项 → 子目」的**教材目录顺序**逐级定位，并看到该子目完整的人材机消耗量。

本系统的目标即第 2 步：**一个只读的、可离线运行的 Web 查询器**。

### 1.1 功能目标

| 目标 | 具体要求 |
| --- | --- |
| 多级联动 | 先选分部（章），再选分项（小节），再选子目；上级变更时下级自动收敛，不允许出现「选了分部却看到别章的分项」 |
| 逐级定位 | 任一点击都有可见反馈；面包屑可回退；URL 可复现当前视图 |
| 消耗量展示 | 展示该子目的人工、材料、机械三类资源，含名称、规格型号、单位、消耗量、序号 |
| 数据可信 | 空值、负值、重复表、章号冲突如实呈现，不静默修补；提供自检面板 |
| 可用性 | 首屏即有内容；3 次点击内到达任意子目；1440/1024/390 三档可用；断网可开 |

### 1.2 非目标

组价与费用计算、数据在线编辑、用户体系、移动端 App。

## 3. 功能设计

### 3.1 层级模型

```
分部 Division（章，7 个）
└─ 分项 Section（小节，35 个，一张工作表 = 一个小节）
   └─ 子目 Item（270 个，编号如 3-689）
      └─ 消耗量 Consumption（2395 条，人工/材料/机械）
```

| 关系 | 基数 | 连接键 |
| --- | --- | --- |
| 分部 → 分项 | 1 : N | `section.divisionId` |
| 分项 → 子目 | 1 : N（1–40） | `item.sectionId` |
| 子目 → 消耗量 | 1 : N（1–30） | `consumption.itemId` |

### 3.2 界面布局（≥1280px，四栏）

```
┌───────────────────────────────────────────────────────────────────────────────┐
│ 安装工程消耗量查询器        2021 河北省消耗量标准 · P30 杨敏悦   [搜索：编号/名称/资源] │
├───────────────────────────────────────────────────────────────────────────────┤
│ ① 分部 C3 建筑智能化  →  ② 分项 C3.7.3.4 视频控制设备安装  →  ③ 子目 3-689 云台控制器 │
├──────────────┬──────────────────┬──────────────────┬───────────────────────────┤
│ 分部（7）     │ 分项（14）        │ 子目（8）         │ 消耗量明细（3-689 云台控制器）│
│ ● C2 电气 89 │ ● 视频控制设备安装 │ ● 3-689 云台控制器│ 单位 台 · 5 项             │
│ ○ C3 智能化80│   C3.7.3.5 …      │   3-690 视频切换器│ 人工  综合用工二类 工日 0.589│
```

| 宽度 | 布局 |
| --- | --- |
| ≥1280 | 四栏并排（分部 / 分项 / 子目 / 明细） |
| 1024–1279 | 三栏：分部收为顶部横条 |
| <768 | 单栏步骤式：一屏一级，顶部步骤条回退 |

### 3.3 联动规则

| 操作 | 分部 | 分项 | 子目 | 明细 |
| --- | --- | --- | --- | --- |
| 首次打开 | 第 2 章（首个有数据章） | 该章首个非重复小节 | 该小节首个子目 | 有内容 |
| 点分部 | 切换 | 落到该章首个小节 | 该小节首个子目 | 切换 |
| 点分项 | 不变 | 切换 | 该分项首个子目 | 切换 |
| 点子目 | 不变 | 不变 | 切换并高亮 | 切换 |
| 搜索命中 | 自动跳到所属分部 | 所属分项 | 命中子目 | 高亮命中资源行 |
| 打开深链接 | 按 URL 恢复 | 按 URL 恢复 | 按 URL 恢复 | 一致 |

任一层级 ID 失效时逐级回退，**不允许右栏空白**。

### 3.4 展示规则

| 场景 | 规则 |
| --- | --- |
| 数字 | 用原表文本展示，不四舍五入、不补零、不加千分位；等宽字体右对齐 |
| 空值 | 显示 `—`，标注「原表此格为空」，不计入合计 |
| 负值 | 原样显示 `-1.02`，标「扣减」，不取绝对值 |
| 单位 | `10m`、`100kg`、`10个` 原样显示，不换算 |
| 合计 | 仅在相同资源单位内求和；跨单位只给「N 项 · kg / m³ / 套」分布 |
| 数据标记 | 「章号不一致」「内容重复」「同编号另有含义」以标签形式出现在详情头部 |

## 4. 实现方案

| 层 | 技术 | 说明 |
| --- | --- | --- |
| 数据构建 | Node 20+ + SheetJS | `scripts/build-data.mjs` 读 3 个 xlsx，产出 4 张表的 JSON + 12 条校验结果 |
| 前端 | React 18 + TypeScript 5 | 组件化拆分四栏与明细 |
| 构建 | Vite 5 | 产物为纯静态文件，数据内联，双击 `dist/index.html` 即可离线使用 |
| 样式 | 原生 CSS + CSS 变量 | 无 UI 框架依赖 |

### 4.1 关键实现点

1. **归章**：`章号 = Number(subitem_code.split('-')[0])`。不使用工作表名推章，否则 9 张表会归错章。
2. **分项主键**：`s-` + 工作表**实名**（保留全角括号、尾点、大小写），因为 `sheet_name` 字段在 3 张表里不可信。
3. **子目主键**：`i-` + 工作表名 + `-` + 编号，解决 `2-92`～`2-98` 跨表同号不同义。
4. **标题回填**：合集同名工作表 A1 → 去「工作内容：」「单位：」尾巴 → 剥 `9.` / `(4)` / `九、` / `②` 前缀 → 拆父子级；查不到时回退「首个子目名 + 等」→ 工作表名。
5. **重复表识别**：对「编码+序号+类别+名称+规格+单位+消耗量」七字段做 sha1 取前 12 位，相同即为内容重复，标记 `dupOf` 并默认折叠。

## 6. 小结

本系统把印刷体的消耗量标准表，转换成「分部 → 分项 → 子目 → 人材机」四级可导航结构，
用 500 KB 的静态数据支撑 2395 条记录的全量检索，不需要服务器、不需要联网。
数据层面把关的重点不是"看起来对"，而是**每一条都能被脚本从原始 xlsx 重新算出来并逐格比对上**。
