# 03 · 数据契约与筛选规则

本文是实现的**唯一口径**：字段怎么定、层级怎么连、数据往哪归、缺陷怎么标、界面怎么显示。
所有结论都由 `scripts/build-data.mjs`（生成）与 `scripts/verify.mjs`（独立对账）双向锁定，
以 2026-11-09 全量实测（2395 条记录 / 35 张数据表）为依据。

---

## 1. 层级模型与主键

```
分部 Division（章，7 个）        id = "d" + 章号              例：d3
└─ 分项 Section（小节，35 个）   id = "s-" + 工作表实名        例：s-C3.7.3.4
   └─ 子目 Item（270 个）        id = "i-" + 表名 + "-" + 编号  例：i-C3.7.3.4-3-689
      └─ 消耗量 Consumption      id = "r-" + 表名 + "-" + 编号 + "-" + 序号
```

| 关系 | 基数 | 连接键 |
| --- | --- | --- |
| 分部 → 分项 | 1 : N | `section.divisionId` |
| 分项 → 子目 | 1 : N（1–40） | `item.sectionId` |
| 子目 → 消耗量 | 1 : N（1–30） | `consumption.itemId` |
| 子目 → 分部（冗余） | N : 1 | `item.divisionId`，避免跨表回溯 |

**为什么子目主键必须带工作表名**：`2-92`～`2-98` 在 `C3.8.1` 系 4 张表与 `C3.8.1（2）` 里都出现，
前者是「母线槽 / 10m」，后者是「分线箱 / 台」。只用编号做主键会串数据。

## 2. 归章：看编号，不看表名

```
章号 = Number( subitem_code.split('-')[0] )
分部 id = "d" + 章号
```

## 3. 分项 = 工作表实名

| 事实 | 影响 | 处理 |
| --- | --- | --- |
| `C3.8.1（3）（4）（5）` 三张表的 `sheet_name` 字段都写成 `C3.8.1`（222 行） | 按字段分组会把 3 张表并成 1 张，子目 270 → 249 | 分项 id 一律用**工作表实际名称**；字段值仅展示 |
| 工作表名写法不统一：`C3.8.1`、`C3.8.1.（尾点）`、`C3.8.1（2）`（全角）、`C3.3.2.5 (2)`（半角+空格）、`c.7.7`（小写） | 归一化会丢主键唯一性 | 逐字保留，深链接里 `encodeURIComponent` |

## 4. 小节标题：回退链

长表没有小节名字段，标题取自 `工程管理信息系统实训二数据合集.xlsx` 同名工作表的 **A1 首个非空行**：

```
取 A1 首个非空行 → 截掉「工作内容：」「单位：」尾巴 → 反复剥编号前缀 → 拆「父级 + 数字.子级」
```

剥前缀规则：`第X节`、`一、`、`9.`、`(4)`、`①`（可多轮叠加）。
查表时对表名做归一化（全角 `（）`↔半角 `()`、大小写、空格），否则 `C3.8.1（2）` 会查不到。

| 顺序 | 来源 | 标记 | 实测 |
| --- | --- | --- | --- |
| 1 | 合集同名工作表 A1 | `source-a1` | 34 张 |
| 2 | 人工核定 `TITLE_OVERRIDES` | `override` | 1 张：`C3.8.1（2）` → 封闭母线槽进出分线箱 |
| 3 | 首个子目名 + 「等」 | `first-item` | 0 张 |
| 4 | 工作表名 | `sheet-name` | 0 张 |

> `C3.8.1（2）` 必须人工核定：合集里它的 A1 与 `C3.8.1` 一字不差，但表内 4 个子目是 `2-95`～`2-98`
> 的「分线箱 / 台」。照抄 A1 会让导航里出现两个同名小节。

## 5. 消耗量与数值语义

| 规则 | 说明 |
| --- | --- |
| 空消耗量 | `qty = null`，`qtyText = ''`。**绝不写 0**，界面渲染 `—`，不计入净合计 |
| 负消耗量 | 原样保留（定额以负值表示扣减），界面标「扣减」，不取绝对值 |
| 数值精度 | 用原表文本 `qtyText` 展示，不四舍五入、不补零、不加千分位 |
| 单位 | 子目单位（`台`/`10m`/`100kg`）与资源单位（`工日`/`套`/`台班`）均原样，不换算 |
| 净合计 | 只在**相同资源单位**内求和，并注明「含负值扣减」；跨单位只给分布 |

## 6. 缺陷标记

| 标记 | 判定 | 数量 | 界面表现 |
| --- | --- | --- | --- |
| `dup-sheet` | 七字段（编码/序号/类别/名称/规格/单位/消耗量）sha1 前 12 位相同 | 3 张 | 默认折叠，可开关；详情标「内容重复」 |
| `chapter-mismatch` | 表名首段数字 ≠ 子目章号 | 9 张 | 橙色标签「章号不一致」 |
| `field-mismatch` | `sheet_name` 字段 ≠ 工作表实名 | 3 张 / 222 行 | 灰色标签「表名字段不符」 |
| `alias-code` | 同编号在不同表里名称或单位不同 | 4 个编号（`2-95`~`2-98`） | 详情里列出其他含义并可跳转 |
| `empty-qty` / `negative-qty` | 数量为空 / 为负 | 372 / 136 条 | 行内 `—` / 「扣减」标签 |

重复表保留项：`C3.8.1`；重复项：`C3.8.1（3）（4）（5）`（各 74 行、7 子目，逐格相同）。

> V12 的矛盾如实呈现：`C3.8.1` 有 74 条备注写着「本页数据已去重」，但三份重复数据仍真实存在于源文件里。
> 查询器备注照录、重复表照标，不做「悄悄修好」。

## 8. 排序契约

| 对象 | 规则 |
| --- | --- |
| 分部 | 章号升序（2 < 3 < … < 8） |
| 分项 | 表名编码数字段自然序（`C3.7.3.4 < C3.7.3.10`），同族再比括号序号（`C3.8.1 < C3.8.1（2）`） |
| 子目 | 编号数字段（`2-9 < 2-10`） |
| 消耗量 | `record_no` 转数值后升序（避免 `"10" < "9"`） |
| 搜索结果 | 编号精确 100 → 编号前缀 80 → 编号包含 60 → 子目名 50 → 资源名 30+，同分按编号 |

## 9. 前端接口（`src/data/index.ts`）

| 方法 | 说明 |
| --- | --- |
| `listDivisions()` | 7 个分部，含表数/子目数/记录数 |

| `listItems(sectionId)` | 该分项的子目 |
| `listConsumptions(itemId)` | 该子目的明细，已按序号升序 |
| `resolveSelection(route, includeDup)` | 三级选中解析，任一层失效逐级回退，保证右栏不空 |
| `search(keyword, limit)` | 三路搜索，返回 `{ hits, total }` |
| `unitTotals(list)` | 同单位求和，跨单位分列 |
| `itemToText / itemToCsv` | 复制文本 / 导出 CSV（UTF-8 BOM） |
